# 網羅調査の範囲と残る確認事項

2026-10-15時点の公開Webアプリを対象に、画面の実通信と配信JavaScriptの両方からAPIを調べた。ソース定義133種類、実通信のみで確認した1種類を合わせ、[総索引](catalog.md) に134種類を整理した。

この134種類は、ホスト・HTTPメソッド・クエリを除いたパスの組み合わせで数える。IDやクエリ値の違いは同じルート、GETとPOSTは別ルート。汎用の教材種別パラメーターは、対応する全種類へ推測で展開していない。

## 何をどこまで調べたか

| 対象 | 確認範囲 |
| --- | --- |
| 公開Web本体 | `ohtomi@9.21.0` の本体1本 |
| 遅延ロードされるWeb機能 | 本体のJavaScriptローダーが列挙する64本をすべて取得・解析 |
| 教材UI | 演習・選択記述・論述のKokubanバンドル3本 |
| 合計 | 68本、9,957,701バイト。URL・SHA-256は `inventory.json` |
| HTTP呼び出し | ASTで167箇所を抽出し、重複と動的パスを精査 |
| API実通信 | 92件。初回・動画・テスト・追加読み取りの観測を統合 |
| 教材HTML等 | 別途14件の観測。認証入口は下記の別確認 |

教材JSON、本文HTML、再生位置、テスト結果、アカウント、所属検索、通知、フォーラム、定期テスト一覧、問い合わせ、商品の表示を調べた。動画・提出物の調査手順はそれぞれの詳細資料に残している。

## 確認状況を三段階で表示する

| 区分 | ルート数 | 意味 |
| --- | ---: | --- |
| 成功観測 | 50 | 少なくとも1件の2xxを観測。サンプルの権限・パラメーターに限る |
| エラー／送信観測 | 9 | 403・404・中断などの実通信を確認。成功を保証しない |
| コードのみ | 75 | 配信物に定義あり。HTTP成功や現在の利用は未確認 |

ソースの各ルートは、関数名、引数、クエリ式、本文・options式、元ファイルとUTF-16オフセットを持つ。クライアントが引数をそのまま転送するだけの箇所には、未確認の本文型を付けていない。

授業用の汎用パス生成関数はコードを読み、課外の `lessons/{id}` と必修／ZEN大学の `n_school/courses/.../lessons/{id}` に展開した。論述送信も呼び出し側で確認した2種類へ展開した。展開根拠は `scripts/api-inventory/reviewed-expansions.json` と各定義の `expansionEvidence` にある。

## 自動抽出と実通信を照合する

資料は次の順で作成する。

1. 本体JSのローダーからJavaScriptのファイル名・ハッシュを読む。CSSのハッシュ表と区別する。
2. JSを実行せず、構文木でHTTPメソッド呼び出しとAPIパス文字列を調べる。大文字の生成クライアント `GET` / `POST` も含める。
3. 定義の重複をまとめ、クエリをパスから分離し、レビュー済みの動的パスを展開する。
4. `*observations.json` のメソッド・ホスト・パスと照合する。汎用パスより具体的な定義を優先する。
5. 機能別の総索引と機械可読な参照を生成する。

`POST`であることだけでは読み書きの意味は確定しない。たとえば履歴検索はPOST定義だが、今回は送信せずコード上の候補として記録した。debug系3ルートも配信物内で見つかったが、実行していない。

## 認証・外部連携はAPI一覧と分ける

未ログインの隔離コンテキストで `/login` と `/register` の200を確認した。認証入口 `/oauth_login` のproviderリンクも読んだが、OAuthの新規認可は開始していない。認証callback、Cookie発行・更新、失効の全契約はこの調査からは確定できない。

決済フォーム、署名付きアップロード先、HLS・コメント接続先のように、サーバーが返すURLや外部サービスの処理は、固定パスのJSON APIとは別に [platform.md](platform.md) と [video.md](video.md) に記載した。Google Analytics、Clarity、Sentry等の分析通信はZEN Studyの業務API件数へ含めない。

`/my_course/progress_overview` と `/kd-edu/event-calendar` は今回表示を試したが、目的のデータ通信を確認できなかった。画面側の404や表示条件を、関連APIの存在・不存在と同一視しない。

## サーバー全体の「全API」を断定しない

今回、配信本体が参照する64本の追加JSと、観測した教材UI3本はすべて解析した。一方、次は公開Webソースと現在の単一セッションだけでは確認できない。

- ネイティブアプリ専用、管理者・講師専用、サーバー間通信、公開ソースから参照されないAPI。
- 別の所属・学年・契約・機能フラグでのみ返る項目や画面。
- 現在配信されていない別バージョン、未公開のURL、廃止されたルートの運用状態。
- 実行していない変更系の成功応答、必須条件、エラー全種類、冪等性、レート制限。
- ライブ配信中のWebSocket、コメント送受信、アンケートやクイズの全プロトコル。

提出、投稿、通報、設定保存、削除、購入、顔認証、debug操作を行わずに調べられる範囲を、今回の索引へ集約した。次は「コードのみ」のルートごとに、実行してよいテスト用データと権限を用意し、成功時の本文・レスポンス・状態変化を追加すればよい。

## 更新・再現方法

[抽出ツールのREADME](../../scripts/api-inventory/README.md) に実行手順がある。生成したJS本体はリポジトリへ保存せず、URLとSHA-256だけを残す。生のHAR、Cookie、トークン、解答・成績・プロフィールの実値も保存しない。

`inventory.json` は静的定義、`catalog.json` は実通信との対応、`catalog.md` はその表示版。ソースが変わった場合は、抽出・展開根拠のレビュー・観測との照合をやり直す。旧記録を上書きして、未検証の新バージョンを成功確認済みとして扱わない。
